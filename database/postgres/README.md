# PostgreSQL — создание базы (Этап 1)

## Как применить

```
psql -U <ваш_пользователь> -d <имя_базы> -f 001_initial_schema.sql
psql -U <ваш_пользователь> -d <имя_базы> -f 002_users_roles.sql
```

(или через pgAdmin / DBeaver — просто выполнить оба файла по очереди в Query
Tool на нужной базе; сначала `001`, потом `002`).

Саму базу данных (`CREATE DATABASE ...`) нужно создать заранее — эти
скрипты создают только таблицы внутри неё.

**Если база уже была создана раньше** (`001`/`002` уже выполнялись до
исправления TEXT → VARCHAR, см. `003` ниже) — примените ещё и:

```
psql -U <ваш_пользователь> -d <имя_базы> -f 003_fix_text_columns.sql
```

Иначе будет падать `EDatabaseError: Type mismatch ... expecting:
WideString actual: WideMemo` при открытии почти любого запроса со
строковыми полями. На новых базах, где `001`/`002` выполняются впервые
(уже с VARCHAR), файл `003` не нужен.

Также если база была создана до исправления денежных полей (`001` со
старым `NUMERIC(18,2)` вместо `MONEY` для `base_salary` и полей
`payroll_journal`) — примените и:

```
psql -U <ваш_пользователь> -d <имя_базы> -f 004_fix_currency_columns.sql
```

Иначе часть запросов падает с `Type mismatch ... expecting: Currency
actual: FMTBcd` (или наоборот, `expecting: FMTBcd actual: Currency`,
если чинить это одним общим правилом на всё подключение — оба типа
несовместимы в рамках одной группы полей, нужно разделять именно на
уровне типа колонки).

## Что внутри

- **`001_initial_schema.sql`** — точный перевод действующей схемы SQLite
  (`database/schema/salarydb_schema_only.sql`, реальный экспорт из рабочей
  `salarydb.db`) на PostgreSQL. Имена таблиц и колонок не менялись —
  весь код на Delphi, обращающийся к ним по имени, продолжит работать.
  Строковые колонки — `VARCHAR(N)` с запасом по длине, а не голый `TEXT`
  (у голого `TEXT` в Postgres нет объявленной длины, и FireDAC мапит его
  в `WideMemo`, а не в `WideString`, которую ждёт старый код). Денежные
  поля, которые в SQLite были типом `CURRENCY` (а не `DECIMAL`) —
  `MONEY`, а не `NUMERIC(18,2)` (см. `004` ниже, почему это важно).
- **`002_users_roles.sql`** — новые таблицы `app_users` (логин/пароль/роль)
  и `audit_log` (журнал аудита) для многопользовательской работы. Заведён
  пользователь по умолчанию `admin` / `admin` (пароль обязательно сменить
  после первого входа, когда появится экран смены пароля).
- **`003_fix_text_columns.sql`** — миграция для баз, созданных ДО этого
  исправления: переводит те же колонки из `TEXT` в `VARCHAR(N)` на уже
  существующей базе (`001`/`002` используют `CREATE TABLE IF NOT EXISTS`
  и повторный запуск их не обновит).
- **`004_fix_currency_columns.sql`** — миграция для баз, созданных ДО
  исправления денежных типов: переводит `base_salary` и денежные поля
  `payroll_journal` из `NUMERIC(18,2)` в `MONEY` на уже существующей базе.

Подключение к PostgreSQL уже реализовано в `UnitdmMain.pas`
(`Driver=PG` в `config.ini`, см. `Win32/Debug/config.ini.example`) —

для входа в программу подключим отдельным шагом (сейчас логин

единственное, что временно не тронуто в этом этапе).
