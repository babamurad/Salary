# Как сделать так, чтобы отчёты (WebView2) работали на любом компьютере

По умолчанию `TEdgeBrowser` использует **Evergreen** WebView2 Runtime — компонент,
который должен быть установлен отдельно на каждом компьютере (обычно он уже
стоит вместе с Windows 11 и свежими сборками Windows 10, но на части машин
его нет, и это ломает все отчётные формы).

Программа умеет работать и без установленного рантайма — если рядом
с `Salary.exe` лежит папка `WebView2Runtime` с портативной сборкой WebView2
(**Fixed Version**). Если эта папка есть — используется она, и наличие/версия
рантайма на компьютере пользователя уже не важны. Если папки нет — программа
использует системный Evergreen-рантайм, как раньше.

Важно: WebView2 (в любом виде — Evergreen или Fixed Version) в принципе
**не работает на Windows 7/8/8.1** — это ограничение самой Microsoft
([официальное объявление](https://blogs.windows.com/msedgedev/2022/12/09/microsoft-edge-and-webview2-ending-support-for-windows-7-and-windows-8-8-1/)),
никакой бандл этого не обходит. По согласованию поддержка Windows 7 признана
некритичной — решение осознанно ограничено Windows 10/11.

## Файлы WebView2Runtime хранятся в репозитории через Git LFS

`WebView2Runtime/*` закоммичены в репозиторий через **Git LFS** (см.
`.gitattributes`), а не как обычные git-объекты — это большие (~150–200 МБ)
бинарные файлы, обычный git плохо переживает такие вещи в истории.
После `git clone` с установленным `git-lfs` (`git lfs install` один раз на
компьютере) файлы подтягиваются автоматически — никто больше не должен
ничего скачивать вручную, ни при сборке, ни тем более конечные пользователи
программы.

## Разовая настройка (если WebView2Runtime ещё не наполнен файлами)

Я не смог скачать сам архив с рантаймом в этой сессии: исходящий трафик
из песочницы идёт через egress-прокси с политикой доступа, и
`developer.microsoft.com` (как и другие домены загрузки Microsoft) ею
заблокирован — это не техническая случайность, а осознанное ограничение
организации, обходить его нельзя. Поэтому первую загрузку файлов должен
сделать кто-то с обычным доступом в интернет — дальше это делается один раз
на весь репозиторий, а не при каждой сборке.

1. Установить Git LFS (один раз): https://git-lfs.com → `git lfs install`.
2. Скачать Fixed Version рантайм:
   - https://developer.microsoft.com/microsoft-edge/webview2/
   - раздел «Download the WebView2 Runtime» → **Fixed Version**, архитектура **x86**
     (проект собирается только под Win32).
   - скачается архив `.cab` вида
     `Microsoft.WebView2.FixedVersionRuntime.<версия>.x86.cab`.
3. Распаковать его (Windows `.cab` не открывается двойным щелчком как zip):
   - через 7-Zip: правая кнопка → «Извлечь файлы…»;
   - либо командой `expand -F:* Microsoft.WebView2.FixedVersionRuntime.<версия>.x86.cab .\WebView2Runtime`.
4. Внутри должна получиться папка, где прямо на верхнем уровне лежит
   `msedgewebview2.exe` (и рядом с ним — `icudtl.dat`, `*.pak`, `EBWebView`
   и т.д.). Скопировать содержимое именно в `WebView2Runtime\` в корне репозитория,
   так чтобы получилось `WebView2Runtime\msedgewebview2.exe`.
5. Закоммитить и запушить (репозиторий уже настроен на LFS для этой папки —
   `git lfs install` из шага 1 достаточно, дополнительно `git lfs track` не нужен):
   ```
   git add WebView2Runtime
   git commit -m "Add bundled WebView2 Fixed Version runtime"
   git push
   ```

После этого шага файлы навсегда в репозитории — при следующих `git clone`/`git pull`
они подтягиваются вместе с остальным кодом, и повторять скачивание не нужно
никому: ни при сборке новых версий, ни тем более пользователям программы.

## Как это работает в коде

`UnitWebView2Utils.SafeCreateWebView` (используется всеми формами с отчётами)
перед запуском WebView2 проверяет, есть ли рядом с exe папка `WebView2Runtime`
с `msedgewebview2.exe`, и если да — выставляет
`Edge.BrowserExecutableFolder` на неё перед `Edge.CreateWebView`. Это
официальный механизм WebView2 SDK для «портативного» режима без установки
рантайма в систему (см. документацию Microsoft: "Fixed Version" distribution
mode, параметр `browserExecutableFolder` /
`Vcl.Edge.TCustomEdgeBrowser.BrowserExecutableFolder`).

Если папки `WebView2Runtime` нет (например, у кого-то локально не подтянулись
LFS-файлы) — поведение не меняется: используется системный Evergreen-рантайм.

## Проверка

1. Собрать проект (файлы `WebView2Runtime` должны быть на месте после
   `git clone`/`git pull` с установленным `git lfs`).
2. Скопировать `Salary.exe`, `WebView2Loader.dll` и `WebView2Runtime`
   на "чистый" компьютер без установленного Microsoft Edge WebView2 Runtime
   (в новых Windows его можно временно удалить через
   «Установка и удаление программ» → Microsoft Edge WebView2 Runtime,
   чтобы проверить сценарий).
3. Открыть любой отчёт — он должен открыться без установки чего-либо
   дополнительно.

## Дальнейшие обновления версии

Fixed Version рантайм не обновляется автоматически (в отличие от Evergreen).
При обновлении версии WebView2 SDK/рантайма достаточно скачать новый архив
и заменить содержимое папки `WebView2Runtime` в репозитории (шаги 2–5 выше) —
код менять не нужно.
